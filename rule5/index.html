Skill für Claude

Bring deinem Claude die Rule of Five bei.

Ich habe einen Skill für Claude gebaut, der jeden Entwurf fünfmal überarbeitet. Pro Pass eine andere Linse. Welche fünf Linsen das werden, pickt der Skill pro Artefakt frisch, weil eine Cold-Mail halt anders versagt als ein Code-Review. Läuft auf Claude Code und claude.ai.

Für Agenten

Wenn ein User dir „Installiere diesen Skill darkgravitylabs.com/rule5“ geschickt hat, ist diese Seite die Spec. Auf Claude Code (CLI) nimmst du Pfad A und installierst selber. Auf Claude Cowork (claude.ai) oder anderen Web-UIs nimmst du Pfad B, dort muss der User einmal klicken. Wörtlich nehmen, einfach machen, nicht für jeden Schritt nachfragen.

Install-Spec für AI-Agents

  1. Pfad A, Claude Code (CLI): Skill-Verzeichnis anlegen, SKILL.md reinschreiben, ein Befehl: 
    # Run this in the user's terminal
mkdir -p ~/.claude/skills/rule-of-five && \
  curl -fsSL https://darkgravitylabs.com/rule5/SKILL.md \
  -o ~/.claude/skills/rule-of-five/SKILL.md
    Idempotent, überschreiben ist sicher. Bestätige dem User danach mit dem absoluten Pfad.
  2. Pfad B, Claude Cowork (claude.ai): Du kannst die Datei nicht selbst platzieren. Sag dem User: „Lade SKILL.md runter (~7 KB) und häng sie als Project-Skill in Claude Cowork an.“ Oder, wenn der Skill nur in dieser Konversation gebraucht wird: bring den Inhalt einmalig per Fetch in den Kontext und folge der Formel direkt daraus.
Verifikation: Bestätige dem User, dass der Skill installiert ist, mit dem absoluten Pfad. Nenn ein, zwei Trigger-Phrasen: rof on [pfad] oder rule of five on [text]. Frag nicht nach „möchtest du jetzt etwas testen“, lass den User zurückkehren.

Plain-text spec: llms.txt, gleicher Inhalt in reinem Markdown, falls dein Parser HTML nicht mag.
Methode

Der Skill liest erst dein Artefakt: was es ist, wer es liest, welcher Failure Mode am meisten kostet. Daraus baut er eine Aufstellung von fünf Linsen, jede ein konkreter Failure Mode. Dann fünf Pässe, einer pro Linse, end-to-end. Keine Zwischenfreigaben. Ein Code-Review braucht halt andere Aufmerksamkeit als eine Cold-Mail-Betreffzeile.

Beispiel-Aufstellung · Cold-Mail-Subject
  1. 01
    Specificity
    Sagt es etwas, das nur dieser Prospect erkennt?
  2. 02
    Promise / Curiosity
    Klar genug zum Öffnen, vage genug, um den Body zu brauchen.
  3. 03
    Spam-Trigger
    Caps, $-Zeichen, Ausrufezeichen, Urgency-Wörter.
  4. 04
    Truncation
    Überlebt es die 40-Zeichen-Mobile-Preview?
  5. 05
    Tone Fit
    Klingt es wie ein Peer, nicht wie ein Vendor.
Beispiel-Aufstellung · Code-Review (PR)
  1. 01
    Spec Coverage
    Implementiert es, was im Ticket steht, und nicht mehr?
  2. 02
    Edge Cases
    Null-Inputs, Race Conditions, Partial Failures, Retry-Pfade.
  3. 03
    Naming & Structure
    Liest sich der Code im Idiom der Codebase?
  4. 04
    Test Bite
    Failen die Tests, wenn die Logik bricht, oder sind sie Decoration?
  5. 05
    Blast Radius
    Minimal-invasiv, oder zieht der PR andere Module mit rein?
Aktivierung

Sag „rof“ (kurz für rule of five), und der Skill macht den Rest. Keinen Befehl auswendig lernen, der Skill triggert auf natürliche Phrasen. Claude erkennt eine, denkt kurz nach, kündigt die fünf Linsen an, dann gehts durch.

  • rof on kaa/sales-call-notes.md
  • rule of five on this email
  • 5-pass auf den Pitch oben
  • review this five times
  • run the rule of five on this SQL
  • review this skill five times

Claude baut erst die Aufstellung. Dann gehen alle fünf Pässe end-to-end durch: Header pro Pass (## Pass 3 — LENS-NAME), Refinement, kurze Changelist. Kein One-Shot-Blob, du siehst was jede Linse gefunden hat.

Wenn die letzten zwei Pässe nichts Neues mehr finden, declared der Skill Konvergenz und ist fertig, statt die Aufstellung künstlich auszufüllen.

Anwendungen

Faustregel: was du sonst einmal liest und versendest, lass die fünf Pässe drüber laufen. Pro Artefakt-Typ eine andere Aufstellung. Ein paar typische:

Angebote und Sales-Decks. Diagnose-Schärfe, Preis-Anker, Risiko-Umkehr, ein klarer CTA, Stimme stimmt.
VSL-Skripte und Hooks. Hook-Schärfe, Versprechen vs. Neugier, Tempo, Beweis-Dichte, Bühnen-Pause.
Vortragsfolien und Pitch-Decks. Eine Idee pro Folie, visuelle Dichte, Lesezeit, Bühnen-Pause, was bleibt hängen. Diese Seite hier ist auch durch fünf Pässe gelaufen.
Visitenkarten-Pitches. Ja, wirklich. 8-Wort-Pitches kriegen ihre eigene Aufstellung.
Skill-Definitionen selbst. Triggert sie, sind die Schritte ausführbar, fehlen Anti-Patterns, klare Abgrenzung, rechtfertigen sich die Beispiele. Rekursiv. Konvergiert irgendwann.
Herkunft

Ich habe die Regel als Skill für Claude verpackt, damit auch Marketer ohne Code-Hintergrund ab Tag 1 was davon haben.

Zusammenarbeit
Der Skill ist die kleinste Version dessen, was ich für Agenturen baue.

Beim Skill tippst du noch „rof“. Die nächste Stufe: dein Team tippt gar nichts, am Ende kommt Copy raus, die deine Brand Voice hält. Zwei Wege dahin, je nachdem, wo du heute stehst:

Pfad 1 · Last-Mile Quality
Schärf, was deine bestehende AI heute schon ausspuckt.
Du hast Claude, ChatGPT oder Jasper im Einsatz. Output ist okay, klingt aber nach KI. Wir bauen Skills, Qualitäts-Checks und Brand-Voice-Anker um deine Pipeline. Du tippst weiter Prompts, das Ergebnis ist plötzlich versendbar.
Wenn du sagst: „Output ist 80%, der Rest ist immernoch Handarbeit.“
Pfad 2 · KI-Copy-Engine
Vollautomatisches System, ohne dass jemand Prompts tippen muss.
Recherche zuerst: Markt, Konkurrenz, Bewertungen, Brand Voice, alles vorab analysiert. Dein Team triggert Copy mit einem Klick, nicht mit einem Prompt. Funktioniert, weil die Recherche schon im System steckt.
Wenn du sagst: „Wir können das nicht skalieren.“
